AutoRia Clone — Платформа з продажу автомобілів.

Повнофункціональний REST API бэкенд та SPA-фронтенд для платформи з продажу автомобілів, спроєктований із урахуванням
високих навантажень, гнучкої архітектури ролей/пермішенів та майбутньої контейнеризації для AWS.

Основні особливості та Реалізовані Вимоги (ТЗ)

1. Гнучка Система Ролей та Пермішенів (Permissions):

Для підтримки розширення платформи в майбутньому (додавання автосалонів з менеджерами, механіками, сейлами)
архітектура побудована не на жорстких ролях, а на системі прав доступу (Permissions/RBAC):

Покупець (Buyer) — перегляд оголошень, фільтрація, зв'язок з продавцем.
Продавець (Seller) — створення та управління власними оголошеннями.
Менеджер (Manager) — модерація невалідних оголошень, моніторинг підозрілого вмісту, бани.
Адміністратор (Admin) — повний доступ до системи, створення менеджерів, додавання нових марок/моделей.

2. Типи Акаунтів:

Basic (Базовий) — встановлюється за замовчуванням. Дозволяє опублікувати лише 1 оголошення. Статистика закрита.

Premium (Преміум) — платний акаунт. Надає можливість публікувати необмежену кількість оголошень та відкриває доступ до
аналітики.

3. Автоматична Модерація та Конвертація Валют:
   Модерація тексту: Кожне оголошення автоматично перевіряється на нецензурну лексику.

Якщо знайдено заборонені слова — надається 3 спроби редагування.
Якщо після 3-ї спроби текст не виправлено, оголошення блокується (статус INACTIVE) і відправляється сповіщення менеджеру
на email.

4. Мультивалютність та курс ПриватБанку:

Продавець вказує ціну в одній з валют (USD, EUR, UAH).
Система автоматично вираховує еквівалент в інших валютах за актуальним курсом ПриватБанку (курсы оновлюються щодня за
допомогою запланованого таска/Cron).
У кожному оголошенні зберігається та відображається оригінальна ціна, обрана валюта, підраховані ціни та дата/курс, за
яким робився розрахунок.

Відсутність марки/моделі: Якщо в списку немає потрібної марки чи моделі, продавець може відправити швидкий запит
адміністрації.

5. Статистика та Аналітика (Тільки для Premium)
   Для Premium-користувачів розраховується та відображається:

Загальна кількість переглядів оголошення.
Динаміка переглядів (за день, тиждень, місяць).
Середня ціна аналогічного авто по регіону (наприклад, Київська область).
Середня ціна аналогічного авто по всій Україні.
Технологічний Стек:

Backend: Node.js, Express, TypeScript, Mongoose.

Database: MongoDB Atlas (NoSQL) — обрано для забезпечення високої гнучкості схем даних та легкої масштабованості.

Frontend: React, TypeScript, Vite, Tailwind CSS.

Architecture: Модульна архітектура з використанням DTO, Middleware для перевірки пермішенів та мок-фоллбеками для
локальної розробки.

Інструкція із запуску (Quick Start)!

Передумови (Prerequisites)
Переконайтеся, що у вас встановлено Node.js (версії 18+) та npm.

1) Запуск Бэкенду (Backend)
   Перейдіть у папку бэкенду (або корінь проєкту):

Bash
cd autoria-clone-backend
Встановіть залежності:

Bash
npm install
Створіть файл .env у корені бэкенду (за потреби):

Фрагмент кода
PORT=5000
MONGO_URI=mongodb+srv://<username>:<password>@cluster1.rpijwzp.mongodb.net/autoria?retryWrites=true&w=majority
Запустіть бэкенд у режимі розробки:

Bash
npm run dev
Сервер запуститься за адресою: http://localhost:5000 (якщо підключення до бази відсутнє, сервер автоматично перейде на
резервні мок-дані).

2) Запуск Фронтенду (Frontend)
   Відкрийте новий термінал та перейдіть у папку фронтенду:

Bash
cd autoria-frontend
Встановіть залежності:

Bash
npm install
Запустіть клієнтську частину:

Bash
npm run dev
Відкрийте посилання у браузері:

Plaintext
http://localhost:5173
📡 Тестування через Postman Collection
У корені проєкту знаходиться файл AutoRia_API_Collection.json, який містить готові замокані запити для перевірки всіх
эндпоінтів платформи:

Відкрийте Postman.
Натисніть кнопку Import у лівому верхньому кутку.
Перетягніть файл AutoRia_API_Collection.json.

Використовуйте готові ендпоінти:

GET /api/ads — Отримання списку оголошень.
POST /api/ads — Створення оголошення (з перевіркою ліміту Basic/Premium та автомодерацією).
PUT /api/ads/:id — Редагування оголошення (з лічильником спроб 3/3).
GET /api/ads/:id/analytics — Перегляд аналітики (з перевіркою типу акаунту).
POST /api/brands/request — Запит на додавання відсутньої марки/моделі.

Готовність до AWS та Контейнеризації
Структура проекту підготовлена для міграції в хмару AWS:
Конфігурація середовища винесена в .env.
Відсутня жорстка прив'язка до локальної файлової системи.
Додано Dockerfile та docker-compose.yml для розгортання в AWS ECS (Elastic Container Service) або AWS EKS (Kubernetes)
під високі навантаження.
